# Walkthrough - Checkbox Selection Persistence Fix

This walkthrough documents the fix to ensure that checkbox selections are persisted across sorting, filtering, searching, and fragment lifecycle transitions.

## Root Cause
When the list is reloaded (e.g., when the search text changes, sorting changes, or returning to the fragment in `onResume`), the repository creates new `AppInfo`/`BackupInfo` objects. This caused the selection states (`isSelected = true`) of the previous objects to be lost and reset to `false`.

## Changes Made

### 1. Adapter Improvements
- **File modified**: [AppListAdapter.java](file:///x:/Projects_X/0_Active/8_Android_APK/04_Early_Stage/APK_Backup_Restore_APK_GITHUB/app/src/main/java/com/vypeensoft/apkbackuprestore/adapters/AppListAdapter.java)
  - Added a `selectedPackages` `HashSet` to store the package names of selected apps.
  - In `setApps(List<AppInfo>)`, synchronized the `isSelected` state of each new incoming `AppInfo` object with the `selectedPackages` set.
  - In `clearSelection()`, cleared the `selectedPackages` set and reset active item views.
- **File modified**: [BackupListAdapter.java](file:///x:/Projects_X/0_Active/8_Android_APK/04_Early_Stage/APK_Backup_Restore_APK_GITHUB/app/src/main/java/com/vypeensoft/apkbackuprestore/adapters/BackupListAdapter.java)
  - Added a `selectedFileNames` `HashSet` to store the filenames of selected backups.
  - In `setBackups(List<BackupInfo>)`, synchronized the `isSelected` state of each new incoming `BackupInfo` object with the `selectedFileNames` set.
  - In `clearSelection()`, cleared the `selectedFileNames` set and reset active item views.
