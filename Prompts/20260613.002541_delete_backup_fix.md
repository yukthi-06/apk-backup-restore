# Walkthrough - Delete Backup File Lock Fix

This walkthrough documents the changes made to resolve the issue where deleting backup files failed due to active file locks held by the application process.

## Root Cause
When parsing APK metadata via `PackageManager.getPackageArchiveInfo()`, the app:
1. Assigned the APK path to the parsed `PackageInfo`'s `sourceDir` and `publicSourceDir`.
2. Loaded the app icon drawable using `loadIcon()`.

Loading drawables directly from the custom `sourceDir` internally registers the APK's resources and keeps an open `AssetManager` handle (File Descriptor) on the `.apk` file. Since the resulting `Drawable` was held in memory by the `BackupInfo` model within the list adapter, the `AssetManager` remained active, locking the file from deletion on the filesystem.

## Changes Made

### 1. Static Copying of APK Drawables
- **File modified**: [BackupRepository.java](file:///x:/Projects_X/0_Active/8_Android_APK/04_Early_Stage/APK_Backup_Restore_APK_GITHUB/app/src/main/java/com/vypeensoft/apkbackuprestore/repositories/BackupRepository.java)
  - Updated `parseApkMetadata` to copy the loaded `Drawable`'s contents onto a new static `BitmapDrawable` bound to the application context's resources.
  - This removes any reference link to the parsed APK's `AssetManager`/resources from the `BackupInfo` instances in memory, allowing them to be closed and garbage collected.

### 2. Explicit Garbage Collection & Reference Clearing Before Deletion
- **File modified**: [BackupsFragment.java](file:///x:/Projects_X/0_Active/8_Android_APK/04_Early_Stage/APK_Backup_Restore_APK_GITHUB/app/src/main/java/com/vypeensoft/apkbackuprestore/fragments/BackupsFragment.java)
  - In `onDelete()`, cleared/nulled out the icon reference inside the `BackupInfo` model.
  - Called `System.gc()` and `System.runFinalization()` to force the reclamation of unreferenced resources (specifically the native finalizers for the APK's `AssetManager`).
  - Implemented a fallback retry mechanism: if the first `file.delete()` fails, it runs another garbage collection cycle and retries the deletion after a short sleep window.
  - Applied the same reference clearing, garbage collection, and retry logic to the batch delete action in `performBatchDelete()`.
